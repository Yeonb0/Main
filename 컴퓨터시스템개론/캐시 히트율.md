- 전체 [[메모리]] 접근 중 [[캐시 히트]] 가 차지하는 비율
- Cache hit rate = $\frac{hit 성공}{전체 접근}$
- Cache miss rate = 1 - cache hit rate

### 절차
- 판정 예시 : [[직접 사상 캐시]] 기준 (1 set - 1 line)
1. set bit (s) 로 어느 set 인지 [[Searching|탐색]]
	- 여러 block 이 같은 set 에 mapping 가능 ([[Hashing]])
2. valid bit check
	- `valid bit == 1` -> 다음 단계
	- `valid bit == 0` -> [[캐시 미스]]
3. tag bit (t) check
	- 일치 -> [[캐시 히트]]
	- 불일치 -> [[캐시 미스]]
- [[캐시 히트]] -> block offset (b) 로 원하는 [[데이터]] 탐색
- [[캐시 미스]] -> 아래 수행 후 재접근
	1. 해당 set 에 block 적재 (원래 내용 덮어쓰기)
	2. valid bit 0 → 1 로 변경
	3. tag bit (t) [[업데이트]]

### 표기
- 가정 : cache memory 초기에 비어 있음 -> 처음 데이터 항상 [[캐시 미스]]

| 표기 | 의미 |
| --- | --- |
| `sizeof(int) = 4` | 주어진 자료형의 크기 명시 ([[바이트]] 단위) |
| `int value_1 @ 0x8800200C` | main memory 에서 [[변수]]의 자료형 & 주소 명시 |
| `int arr[512] @ 0xAAAA0000` | main memory 에서 [[배열]]의 자료형, 크기, 시작 주소 명시 |

### 계산
- ==ex)== block ==4 byte==, set ==256개==

![[Cache-Memory-20.png]]

- `vals[0]` -> `0100 0000 0010 00|00 0000 10|00` -> s 가 2 -> set 2 에 저장
	- `vals[0-1]` = set 2 / `vals[2-3]` = set 3 / … / `vals[30-31]` = set 17
- 짝수 miss & 홀수 hit -> 16 miss & 16 hit -> ==50%== hit rate

![[Cache-Memory-21.png]]

- 접근 간격만 변경 -> 매번 다른 block 참조 -> 계속 miss -> ==0%== hit rate
	- [[스래싱]] 발생 사례
