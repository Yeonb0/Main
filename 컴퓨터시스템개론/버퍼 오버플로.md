- [[버퍼]] 크기 넘어선 쓰기 -> [[메모리]] 안의 data 손상
- [[C]] 는 [[배열]] boundary check X -> buffer 밖 영역 기록 O
- [[스택 프레임]] 에 저장된 return address 변경 -> [[Control Hijack]]

### 발생 위치
- 주로 [[stack|Stack]] 에 위치한 buffer
	- stack-based buffer overflow : 다른 [[스택 프레임]] 공간 침범
	- cf) stack overflow : stack 에 저장 공간 X

### 원인
- 입력 배열 size 검사 X 인 [[String|string]] handling function
	- `gets()`, `scanf("%s", ...)`, `strcpy()`, `strcat()`
- hacker 의 손쉬운 악용 대상

### ==ex)== 8 byte buffer
```c
void echo(void) {
	char buf[8];
	gets(buf);
	puts(buf);
}

int main() {
	echo();
	return 0;
}
```

```nasm
(gdb) disassemble echo
0x401136: sub  $0x18,%rsp
0x40113a: lea  0x8(%rsp),%rdi       ; stack + 8
0x40113f: mov  $0x0,%eax
0x401144: call 0x401040 <gets@plt>
0x401149: lea  0x8(%rsp),%rdi       ; stack + 8
0x40114e: call 0x401030 <puts@plt>
0x401153: add  $0x18,%rsp
0x401157: ret

(gdb) disassemble main
0x401158: sub  $0x8,%rsp
0x40115c: call 0x401136 <echo>
0x401161: mov  $0x0,%eax
0x401166: add  $0x8,%rsp
0x40116a: ret
```

| 입력 길이 | 결과 |
| --- | --- |
| ==8 글자== | 원래 예상 동작, [[Error\|오류]] X |
| ==9 ~ 15 글자== | 예상 밖 동작, 오류 X |
| ==16 글자 이상== | return address 침범 -> `Segmentation fault` |

- ==16 글자== 입력

