- 여러 자식 요소에 각각 [[이벤트 리스너]]를 다는 대신, 공통 부모에 [[이벤트 리스너]] 하나만으로 자식들의 [[Event|이벤트]] 한 번에 처리
- 원리 : [[이벤트 버블링]] -> 자식에서 발생한 [[Event|이벤트]] 부모가 대신 처리
- 실제로 어떤 자식이 [[Event|이벤트]] 발생 시켰는지는 `event.target` 으로 판단

- 장점
	1. [[이벤트 리스너]] 개수 감소 -> 메모리 / 성능 절약
	2. 동적으로 추가된 요소 처리

```js
// 여러 <li>에 각각 리스너를 다는 대신, 부모 <ul> 하나에만 등록
const list = document.querySelector("#menu");

list.addEventListener("click", (event) => {
  // 실제 클릭된 요소에서 가장 가까운 <li>를 찾음
  const item = event.target.closest("li");
  if (!item) return; // <ul> 여백 등 <li> 밖 클릭은 무시

  console.log("clicked:", item.textContent);
});

// 이후 동적으로 추가돼도 리스너를 다시 달 필요 없음
list.insertAdjacentHTML("beforeend", "<li>새 항목</li>");
```

### Usage

- 리스트·테이블처럼 **같은 종류의 자식 요소가 다수** 반복될 때 (`<ul><li>`, 게시판 행 등)
- `fetch` 등으로 **동적으로 추가/삭제되는 요소**의 클릭을 처리할 때
- 리스너를 수백 개 다는 대신 하나로 줄여 **성능/메모리를 최적화**할 때
- (참고) 리액트의 합성 이벤트(SyntheticEvent)도 내부적으로 이 위임 방식을 사용함
