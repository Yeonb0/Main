- 시스템 변경 · 확장에 유연하기 위해 지켜야할 원칙

### SOLID
- 단일 책임 원칙 (SRP) : Single Responsibility Principle
	- 1 [[객체]] -> 1 책임
	- [[응집도]]↓, [[결합도]]↑ 설계
- 개방-폐쇄 원칙 (OCP) : Open-Closed Principle
	- 기존 코드를 변경하지 않으면서 기능 추가하도록 설계
	- 공통 [[인터페이스]] -> 1개로 [[캡슐화]]
- 리스코프 치환 원칙 (LSP) : Liskov Substitution Principle
	- 자식은 부모가 가능한 행위는 수행 가능
	- 자식은 부모를 무시하고 재정의하는 것이 아닌 확장
- [[인터페이스]] 분리 원칙 (ISP) : Interface Segregation Principle
	- 사용하지 않는 인터페이스와 의존 · 영향 X
	- 1 [[인터페이스]] -> 1 책임
- 의존 역전 원칙 (DIP) : Dependency Inversion Principle
	- 객체 간 의존 시 [[추상화|추상성]] 높은 클래스와 의존 관계
	- [[인터페이스]] 활용 시 준수
