- 사람이 하는 테스트 -> 스크립트 형태 자동화 도구 적용

### 장점
- 작업 자동화 -> 인력 · 시간 ↓
- 테스트 품질 보증, 일관성 · 객관성 확보
- 다양한 표시 형태, 정밀 테스트 O

### 단점
- 교육 · 학습 필요
- 적용 시간 · 비용 · 노력 소요
- 고가 추가 비용

### 고려사항
- [[재사용(Reuse)|재사용]] · 측정 불가능 프로그램 제외
- 용도 맞게 도구 선택
- 프로젝트 초기 테스트 엔지니어 투입 시기 고려

### 도구 유형
| 유형 | 내용 |
| --- | --- |
| 정적 분석 도구 (Static Analysis) | 프로그램 실행 X 분석, 코드 이해해야 분석 O |
| 테스트 케이스 생성 도구 (Test Case Generation Tools) | [[자료 흐름도]], 기능 테스트, 입력 도메인 분석, 랜덤 테스트 |
| 테스트 실행 도구 (Test Execution Tools) | [[데이터]] 주도 접근 방식, 키워드 주도 접근 방식 |
| 성능 테스트 도구 (Performance Test Tools) | 가상 사용자 생성 테스트 -> 성능 목표 달성 확인 |
| 테스트 통제 도구 (Test Control Tools) | 테스트 계획 · 관리, 테스트 수행, [[결함]] 관리, [[형상 관리]] 도구 |
| [[테스트 하네스]] 도구 (Test Harness Tools) | [[드라이버]], [[스텁]], 테스트 슈트, [[테스트 케이스]], 테스트 스크립트, [[목 오브젝트]] |
