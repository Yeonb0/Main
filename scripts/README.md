## 1. 이게 뭘 해주나요

Notion에서 export 한 zip 파일을 `_inbox/` 폴더에 **떨구기만 하면**, 아래가 자동으로 진행됩니다.

```
_inbox/Export-xxx.zip  ←  여기에 던진다
        │
        ├─ ⓪ 정규화 (ingest.py)
        │     · 이미지·첨부 → images/ 로 이동 + 이름 정리
        │     · 깨진 링크 → ![[위키링크]] 로 변환
        │     · 파일명에서 노션 해시 32자 제거
        │
        ├─ ① 사전 갱신 (obsidian_autolink.py)
        │     · 볼트에 이미 있는 개념 목록을 만든다
        │
        ├─ ② LLM 분해 + 기존 노트 보강 (decompose.py, 호출 2번)
        │     · 1패스 : 이 문서로 보강할 기존 노트를 고른다
        │     · 2패스 : 원자 노트 여러 개 + MOC 1개 + 기존 노트 수정판
        │     · 결과는 _pending/ 에 쌓인다 (수정판은 .diff 도 함께)
        │
        ├─ ③ 링크 보강 (obsidian_autolink.py)
        │     · LLM이 놓친 기존 개념에 [[ ]] 를 마저 건다
        │
        └─ ④ 원본을 _inbox/_done/ 으로 이동
                │
                ▼
        _pending/ 에서 사람이 검수 → 볼트로 옮기기 / 덮어쓰기
```

**중요 : 볼트 본체에 직접 쓰는 단계는 ⓪(첨부)뿐입니다.** 노트는 반드시 `_pending/`을 거칩니다.
기존 노트 수정도 마찬가지입니다. 볼트 원본은 절대 자동으로 바뀌지 않고, `_pending/`에 같은
경로로 수정판이 생기고 사람이 확인한 뒤 직접 덮어씁니다.
첨부만 예외인 이유 — `_pending/`에서 검수하는 동안 이미지 미리보기가 보여야 하기 때문입니다.

### 두 가지 결과물

| 종류 | 어디에 | frontmatter 표시 | 검수 후 할 일 |
| --- | --- | --- | --- |
| **신규 노트** | `_pending/<폴더>/새제목.md` | `status: pending` | 볼트로 **옮기기** |
| **기존 노트 수정판** | `_pending/<원본과 같은 경로>.md` | `status: updated` + `base:` | 볼트 원본에 **덮어쓰기** |

수정판 옆에는 `.md.diff` 가 같이 생깁니다. 뭐가 늘었는지 이것만 보면 됩니다.

### 폴더 역할

| 폴더 | 역할 | 사람이 손대나? |
| --- | --- | --- |
| `_inbox/` | Notion export 투입구 | ✅ 여기에 파일을 넣는다 |
| `_inbox/_done/` | 처리 끝난 원본 보관소 | ❌ 자동 |
| `_pending/` | 분해 결과 · 수정판 대기소 | ✅ 여기서 검수하고 볼트로 반영한다 |
| `images/` | 모든 첨부 | ❌ 자동 |
| `_index.tsv` | 개념 사전 (자동 생성) | ❌ 자동 |

## 2. 처음 한 번만 하는 준비

터미널을 열고 볼트 폴더에서 아래를 확인하세요.
**PowerShell을 쓰신다면 `python` 대신 `py`가 필요할 수도 있습니다.**

### 2-1. Python 확인

```powershell
python --version
```

`Python 3.8` 이상이면 됩니다. (현재 확인된 환경 : 3.12.7)
**추가로 설치할 패키지는 없습니다.** 표준 라이브러리만 씁니다.

### 2-2. Claude Code 확인

기본 백엔드(`cc`)는 Claude Code CLI를 씁니다. 구독으로 청구되고 API 키가 필요 없습니다.

```powershell
claude --version
```

명령을 못 찾으면 [Claude Code](https://claude.com/claude-code)를 설치하고 터미널을 새로 여세요.

### 2-3. 잘 도는지 시험 (LLM 호출 없이)

`mock` 백엔드는 고정 응답으로 배선만 확인합니다. **API 비용도, 구독 사용량도 들지 않습니다.**

```powershell
python scripts/watch.py --vault . --once --backend mock
```

`_inbox/`가 비어 있으면 아무 일도 안 일어납니다. 그게 정상입니다.

## 3. 평소 사용법

### 1단계 — Notion에서 export

Notion 페이지 우측 상단 `···` → **Export** → 아래로 설정합니다.

| 항목 | 값 |
| --- | --- |
| Export format | **Markdown & CSV** |
| Include content | Everything |
| Include subpages | 필요에 따라 |

받은 zip 파일을 그대로 씁니다. **압축을 풀지 않아도 됩니다.**

파일명은 `Export-xxx.zip` 또는 `af14dcfd-...ExportBlock-....zip` 처럼 나옵니다. 둘 다 괜찮습니다.
문서가 크면 Notion이 **zip 안에 `Part-1.zip`을 또 넣어서** 주는데, 이것도 알아서 풀립니다.

### 2단계 — `_inbox/`에 넣기

zip을 `_inbox/` 폴더에 복사합니다. 세 가지 형태 모두 인식합니다.

- `Export-xxx.zip` (zip 그대로) ← **권장**
- 압축을 푼 폴더 + md 파일
- md 파일 하나

### 3단계 — 감시 시작

```powershell
python scripts/watch.py --vault . --backend cc
```

3초마다 `_inbox/`를 확인하다가 새 파일이 보이면 알아서 처리합니다.
**끝낼 때는 `Ctrl+C`.**

> **한 번만 처리하고 끝내고 싶다면** `--once`를 붙이세요.
> ```powershell
> python scripts/watch.py --vault . --backend cc --once
> ```

### 실행하면 이런 출력이 나옵니다

```
감시 시작 : ...\_inbox (3.0s 주기, Ctrl+C 로 종료)

=== Export-xxx.zip (zip) ===
  퍼셉트론 3993a748....md  ->  퍼셉트론.md
    + image 1.png  ->  퍼셉트론-01.png
    = image 2.png  ->  퍼셉트론-02.png
  정규화 1개

=== 퍼셉트론.md ===
  [1/4] 보강 대상 선별 (cc) ...
    대상 2개 : AI/신경망.md, AI/가중치.md
  [2/4] LLM 호출 (cc) ...
  [3/4] 응답 파싱 ...
  [4/4] _pending 에 쓰기 ...

  생성 3개 :
    + AI/퍼셉트론.md
    + AI/활성화 함수.md
    + AI/_MOC/퍼셉트론 기초.md

  기존 노트 보강 2개 (볼트 원본은 그대로, 검수 후 덮어쓰세요) :
    ~ AI/신경망.md  (+4줄)
    ~ AI/가중치.md  (+2줄)

  완료 - 원본 이동 : _inbox\_done\퍼셉트론.md
  검수 후 _pending 에서 볼트로 옮기세요 (status: updated 는 덮어쓰기, .diff 로 차이 확인)
```

기호 읽는 법 :

| 기호 | 뜻 |
| --- | --- |
| `+` | 새로 만들었다 / 새로 복사했다 |
| `~` | 기존 노트에 덧붙인 수정판을 만들었다 |
| `=` | 이미 같은 게 있어서 재사용했다 |
| `x` | 보강 제안을 버렸다 (경로가 없거나 바뀐 내용이 없음) |

## 4. 결과 검수하기

`_pending/` 폴더를 열어 확인합니다. **여기 있는 건 아직 볼트가 아닙니다.**

### 4-1. 신규 노트 (`status: pending`)

1. **제목이 링크 이름으로 쓸 만한가** — `2. 메모리 관리` 같은 목차형 제목이면 고치세요.
2. **폴더 위치가 맞나** — 엉뚱한 폴더에 갔으면 옮기세요.
3. **이미지가 보이나** — `![[퍼셉트론-01.png]]` 가 제대로 렌더되는지.
4. **기존 노트와 겹치지 않나** — 겹치면 `볼트에 이미 있어 건너뜀`으로 출력에 나옵니다.

frontmatter의 `status: pending`이 검수 전 표시입니다. 볼트로 옮길 때 지우거나 바꾸세요.

문제가 없으면 **파일을 잘라내서 볼트의 해당 폴더로 옮기면 끝입니다.**

### 4-2. 기존 노트 수정판 (`status: updated`)

frontmatter를 먼저 보세요.

```yaml
status: updated
base: AI/신경망.md          # 덮어쓸 볼트 원본
change: 층 구조 아래에 은닉층 항목 추가   # LLM이 스스로 적은 요약
```

**`.md.diff` 파일을 먼저 열어 보세요.** `+` 줄만 훑으면 검수가 끝납니다.

```diff
### 층 구조
-- 입력층 / 출력층
+- 입력층 / 은닉층 / 출력층
+	- 은닉층 2개 이상 -> [[딥러닝]]
```

확인할 것 :

1. **`-` 줄이 있나** — 기존 내용이 지워졌다는 뜻입니다. 규칙상 나오면 안 되는데,
   링크만 걸린 줄(`- 입력층` → `- [[입력층]]`)은 diff에 `-`/`+` 짝으로 보이니 정상입니다.
   **짝 없이 사라진 `-` 줄이 있으면 그 부분은 반영하지 마세요.**
2. **`guard:` 줄이 있나** — 스크립트가 자동으로 잡은 소실 경고입니다. 있으면 diff를 꼼꼼히 보세요.
3. **중복 추가는 아닌가** — 이미 있는 내용을 표현만 바꿔 또 넣었으면 그 줄만 지우세요.

반영하는 방법 — **수정판 내용을 `base:` 경로의 원본에 덮어씁니다.**
frontmatter의 `source` · `updated` · `status` · `base` · `change` · `guard` 줄은 검수용이니
덮어쓸 때 지우세요. `aliases`와 원래 있던 `tags`는 그대로 살려 둔 상태입니다.

일부만 반영하고 싶으면 diff에서 필요한 `+` 줄만 원본에 복사해 넣으면 됩니다.

## 5. 명령어 사전

### `watch.py` — 전체 파이프라인 (평소엔 이것만 쓰면 됩니다)

```powershell
# 감시 시작 (기본)
python scripts/watch.py --vault . --backend cc

# 지금 쌓인 것만 처리하고 종료
python scripts/watch.py --vault . --backend cc --once

# 폴링 주기를 10초로
python scripts/watch.py --vault . --interval 10
```

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `--vault` | `.` | 볼트 루트 |
| `--backend` | `cc` | `cc`=Claude Code(구독) / `api`=API 키 / `mock`=시험용 |
| `--once` | — | 한 번만 처리하고 종료 |
| `--interval` | `3.0` | 폴링 주기(초) |
| `--images` | `images` | 첨부를 모을 폴더 |
| `--pending` | `_pending` | 결과 대기소 |
| `--no-update` | — | 기존 노트 보강을 끄고 신규 노트만 만든다 (LLM 호출 1번) |
| `--max-context-notes` | `12` | 보강 대상으로 본문을 첨부할 기존 노트 최대 개수 |

### `ingest.py` — 첨부 정리만 (분해 없이)

```powershell
# 뭘 할지 미리 확인 (파일을 건드리지 않음)
python scripts/ingest.py --vault . --dry-run

# 실행
python scripts/ingest.py --vault .

# 특정 zip 하나만
python scripts/ingest.py "_inbox\Export-xxx.zip" --vault .
```

| 옵션 | 설명 |
| --- | --- |
| `--dry-run` | 계획만 출력하고 파일은 안 건드림 |
| `--no-dedupe` | 내용이 같아도 새 파일로 복사 |

### `decompose.py` — md 하나만 분해

```powershell
# 프롬프트만 확인 (LLM 호출 없음)
python scripts/decompose.py "_inbox\퍼셉트론.md" --vault . --show-prompt

# 실행
python scripts/decompose.py "_inbox\퍼셉트론.md" --vault .
```

| 옵션 | 설명 |
| --- | --- |
| `--show-prompt` | 2패스 프롬프트만 출력하고 종료 (1패스 선별은 실제로 호출됩니다) |
| `--overwrite` | 볼트에 같은 제목이 있어도 결과를 생성 |
| `--no-update` | 기존 노트 보강을 끄고 신규 노트만 만든다 (LLM 호출 1번, 비용 절반) |
| `--max-context-notes` | 본문을 첨부할 기존 노트 최대 개수 (기본 12) |
| `--context-chars` | 첨부하는 기존 노트 본문 총 글자 상한 (기본 40000) |
| `--model` | 모델 ID (기본 `claude-sonnet-4-6`, `api` 백엔드에서만 의미 있음) |

> **왜 호출이 2번인가** — 볼트 노트를 전부 프롬프트에 넣으면 너무 크고 비쌉니다.
> 1패스는 사전(제목 목록)만 보고 "이 문서로 보강할 노트"를 고르고,
> 2패스에서 그 노트들의 본문만 첨부합니다. 보강이 필요 없으면 `--no-update` 로 1번만 부르세요.

### `obsidian_autolink.py` — 링크·인덱스 도구

```powershell
# 제목이 중복된 개념 찾기
python scripts/obsidian_autolink.py . --report

# 앞으로 쓸 노트 백로그 (참조 많은 순)
python scripts/obsidian_autolink.py . --unresolved

# 링크 삽입 미리보기 (파일 수정 안 함)
python scripts/obsidian_autolink.py . --only "자료구조"

# 실제로 링크 삽입
python scripts/obsidian_autolink.py . --only "자료구조" --apply
```

> **`--apply`를 붙이지 않으면 절대 파일을 수정하지 않습니다.** 항상 미리보기부터 하세요.

## 6. 문제가 생겼을 때

### 이미지가 깨져서 X 로 보여요

**원인** — `_inbox/`에 md만 넣고 이미지 폴더를 안 넣었을 가능성이 큽니다.
**해결** — Notion에서 zip째로 다시 받아 넣으세요. ingest가 이미지를 못 찾으면 링크를 그대로 두고 넘어갑니다.

### `claude 실행 파일을 찾을 수 없습니다`

**원인** — Claude Code가 설치되지 않았거나 PATH에 없습니다.
**해결** — 설치 후 **터미널을 새로 여세요.** 급하면 `--backend mock`으로 배선만 확인할 수 있습니다.

### `ANTHROPIC_API_KEY 환경변수가 없습니다`

**원인** — `--backend api`를 썼는데 키가 없습니다.
**해결** — `--backend cc`를 쓰세요(구독으로 청구, 키 불필요). 이게 기본값입니다.

### `LLM 응답에서 JSON을 찾지 못했습니다`

**원인** — 모델이 JSON 대신 설명을 뱉었습니다. 문서가 너무 길 때 자주 납니다.
**해결** — 원본은 `_inbox/`에 그대로 남아 있으니 안전합니다. 문서를 반으로 쪼개서 다시 넣어 보세요.

### `md 가 없습니다 - 건너뜀`

**원인** — zip 안에 마크다운 파일이 없습니다. Notion에서 export 형식을 잘못 골랐을 때 납니다.
**해결** — Export format을 **`Markdown & CSV`** 로 다시 받으세요. `HTML`이나 `PDF`로 받으면 이 메시지가 납니다.
메시지에 `(안에 있는 것 : .html, .png)` 처럼 실제 내용이 함께 나오니 확인해 보세요.

### 노트가 `_pending/_inbox/` 같은 엉뚱한 폴더에 생겼어요

**원인** — 이건 고쳐진 버그입니다. `_index.tsv`가 오래된 것이면 재발할 수 있습니다.
**해결** — `_index.tsv`를 지우고 다시 돌리면 새로 만들어집니다.

```powershell
Remove-Item _index.tsv
python scripts/watch.py --vault . --backend cc --once
```

### 아무 일도 안 일어나요

**확인 1** — `_inbox/`에 파일이 실제로 있나요?
**확인 2** — 이미 처리돼서 `_inbox/_done/`으로 옮겨졌을 수 있습니다.
**확인 3** — 정리가 끝난 md는 ingest가 다시 집지 않습니다(무한루프 방지). `바뀔 내용 없음 - 그대로 둠`이 나오면 정상입니다.

### 수정판에 `guard: 기존 줄 N개 소실` 이 붙었어요

**원인** — LLM이 기존 불릿을 지우거나 문장을 다시 썼습니다. 규칙 위반이고, 스크립트가 잡아낸 것입니다.
**해결** — 볼트 원본은 그대로이니 안전합니다. `.md.diff`를 보고 필요한 `+` 줄만 원본에 옮기세요.
수정판 전체를 덮어쓰면 지워진 내용이 같이 날아갑니다.

### 기존 노트를 하나도 안 고쳤어요

**확인 1** — 출력에 `대상 0개` 가 나왔나요? 1패스가 보강할 노트를 못 찾은 것입니다.
문서가 다루는 개념이 볼트에 아직 없으면 정상입니다 (그건 신규 노트로 나옵니다).
**확인 2** — `보강 무시` 목록에 `바뀐 내용 없음` 이 있나요? 이미 노트에 다 있는 내용이라는 뜻입니다.
**확인 3** — `_index.tsv` 가 오래됐을 수 있습니다. 1패스는 사전에 있는 제목만 고릅니다.

```powershell
python scripts/obsidian_autolink.py . --write-index _index.tsv
```

**확인 4** — `--no-update` 를 붙였으면 보강 단계 자체가 꺼집니다. (출력이 `[1/3]` 으로 시작합니다)

### 같은 이름 파일이 여러 개 생겼어요

정상입니다. 이름이 겹치면 `퍼셉트론-2.md`, `퍼셉트론-05.png`처럼 번호를 올립니다. 덮어쓰지 않습니다.

### 되돌리고 싶어요

이 볼트는 git 저장소입니다.

```powershell
git status              # 뭐가 바뀌었는지 확인
git checkout -- <파일>   # 특정 파일만 되돌리기
```

`_inbox/`와 `_pending/`은 `.gitignore` 대상이라 git으로는 되돌아가지 않습니다.
대신 원본이 `_inbox/_done/`에 남아 있으니 거기서 꺼내 쓰세요.

## 7. 안전 장치

파이프라인이 지키는 규칙입니다. 알아두면 마음이 편합니다.

| 장치 | 내용 |
| --- | --- |
| **볼트 직접 수정 없음** | 신규 노트도 기존 노트 수정도 무조건 `_pending/`을 거칩니다. 첨부(`images/`)만 예외. |
| **수정은 추가만** | LLM에게 기존 불릿 삭제 · 문장 재작성 · 섹션 순서 변경을 금지합니다. 허용은 불릿 추가 · 링크 걸기 · aliases 추가뿐. |
| **삭제 자동 검사** | 원본 줄이 수정판에서 사라졌는지 대조합니다 (링크만 걸린 줄은 같은 줄로 봅니다). 사라지면 `guard:` 경고와 함께 출력에 표시합니다. |
| **diff 동반** | 수정판마다 `.md.diff` 를 남겨 눈으로 대조할 수 있게 합니다. |
| **frontmatter 보존** | 수정판은 원본 frontmatter를 그대로 두고 aliases만 합칩니다. LLM이 frontmatter를 쓰지 못합니다. |
| **경로 검증** | `updates` 의 target이 볼트에 실제로 없거나 `..` 를 포함하면 버립니다. |
| **원본 보존** | 처리한 원본은 지우지 않고 `_inbox/_done/`으로 옮깁니다. |
| **덮어쓰기 없음** | 이름이 겹치면 번호를 올립니다. |
| **중복 방지** | 볼트에 같은 제목 노트가 있으면 건너뛰고 목록에 보고합니다. |
| **첨부 중복 방지** | 내용(sha256)이 같은 파일은 다시 복사하지 않고 기존 걸 가리킵니다. |
| **재실행 안전** | 이미 정리된 파일은 다시 건드리지 않습니다. |
| **실패 시 보존** | 분해에 실패하면 원본을 `_inbox/`에 그대로 남깁니다. |
| **dry-run 지원** | `ingest.py --dry-run`, `decompose.py --show-prompt`, autolink는 `--apply` 없이 미리보기. |

## 부록 — 분해 규칙을 바꾸고 싶을 때

LLM이 지키는 노트 작성 규칙은 `decompose.py` 상단의 `RULES` 문자열에 전부 들어 있습니다.
결과물의 문체·형식이 마음에 안 들면 여기를 고치세요.
기존 노트를 어디까지 고칠 수 있는지는 `RULES` 안의 **`## 기존 노트 보강 (updates)`** 절,
보강 대상을 고르는 기준은 그 아래 `SELECT_RULES` 에 있습니다.

```powershell
# 바꾼 규칙이 프롬프트에 잘 반영됐는지 확인 (LLM 호출 없음)
python scripts/decompose.py "_inbox\아무거나.md" --vault . --show-prompt
```

규칙에 담긴 주요 내용 :

- 1노트 = 1개념, 목차형 제목 금지
- 사전(`_index.tsv`)에 있는 개념은 이름을 그대로 재사용
- 본문은 불릿 리스트, 명사형으로 끝내기 (`~이다` 금지)
- 코드블록·수식은 원문 보존
- 이미지는 `![[파일명]]` 위키링크
- MOC는 설명 없이 링크 인덱스로만
